### Выбор: Платформа Сфера (Т1 / НОТА)

**Обоснование:**

Сфера — российская платформа от ИТ-холдинга Т1, входит в ЕРРП (реестр отечественного ПО). Закрывает все требования одним продуктом без необходимости интеграции сторонних инструментов. Реальные внедрения в крупных российских компаниях: ВТБ (20 000+ пользователей, 25 000+ репозиториев, 29 000+ сборок в день), Почта Банк, Росгосстрах.

GitLab рассматривается как второй вариант — зрелое международное решение с широкой документацией и комьюнити, однако не входит в ЕРРП и несёт риски ограничения доступа для российских компаний.

## Задача 2: Логи

### Выбор: Vector + Elasticsearch + Kibana

**Схема взаимодействия:**

```
[сервис stdout]
      |
   Docker
      |
   Vector  ── буфер на диске ──► Elasticsearch ◄── Kibana (UI)
                                                        |
                                                 разработчики
```

| Требование | Как реализуется |
|---|---|
| Сбор логов со всех хостов | Vector-агент на каждом хосте |
| Сбор из stdout | Vector читает stdout контейнеров через Docker socket |
| Гарантированная доставка | Vector буферизует данные на диске при недоступности Elasticsearch |
| Поиск и фильтрация | Elasticsearch — полнотекстовый поиск, фильтрация по полям |
| Пользовательский интерфейс | Kibana с разграничением доступа для разработчиков |
| Ссылка на сохранённый поиск | Kibana Saved Searches — постоянный URL |

**Обоснование:**

Vector выбран вместо классического Logstash: написан на Rust, потребляет значительно меньше RAM, имеет встроенную буферизацию на диск и проще конфигурируется. Elasticsearch обеспечивает надёжное хранение и быстрый поиск. Kibana даёт UI с разграничением доступа и сохранёнными поисками.

## Задача 3: Мониторинг

### Выбор: Prometheus + Grafana + Node Exporter + cAdvisor

**Схема взаимодействия:**

```
[хост]                        [хост]
  |                              |
Node Exporter               Node Exporter
cAdvisor                    cAdvisor
сервис /metrics             сервис /metrics
  |                              |
  └──────────┬───────────────────┘
             |
         Prometheus  (scrape + хранение)
             |
          Grafana  (UI, дашборды, алерты)
```

| Требование | Как реализуется |
|---|---|
| Сбор метрик со всех хостов | Node Exporter на каждом хосте, Prometheus scrape по расписанию |
| CPU, RAM, HDD, Network хоста | Node Exporter — системные метрики хоста из коробки |
| CPU, RAM, HDD, Network сервиса | cAdvisor — метрики потребления ресурсов каждого контейнера |
| Метрики, специфичные для сервиса | сервис экспортирует /metrics в формате Prometheus |
| UI с запросами и агрегацией | Grafana + PromQL |
| Настраиваемые панели | Grafana Dashboards, готовые шаблоны из Marketplace |

**Обоснование:**

Prometheus — стандарт де-факто для мониторинга в микросервисных архитектурах. Pull-модель упрощает добавление новых сервисов. Node Exporter и cAdvisor покрывают метрики хоста и контейнеров без изменений в приложениях. Grafana обеспечивает гибкий UI с алертингом и разграничением доступа.
